# 100% 不透明度下细线偏淡的修复

`v0.3.0-independent.2` 修复桌面和独立覆盖模式的细线半透明问题。两个模式共用 `CrosshairView`，因此同时生效，编辑器预览也采用同样的绘制方式。

## 原因

颜色只接受 `#RRGGBB`，自身 alpha 始终为 255；不透明度也正确由 0–100 转成 0–1。问题来自默认的几何抗锯齿：一条以整数坐标为中心的 1 px 线会分摊到相邻的两个像素。实测旧版在 100% 不透明度、无描边时，这些像素的最高 alpha 只有 128；1.5 px 线最高为 191，而 2 px 线存在 alpha 255 的实色像素。启用黑色描边时，细线颜色还可能与描边混合而显得偏暗。

这可以在同一台显示器上仅通过改变线宽复现，不能据此归因于显示器品牌。DPI 缩放、线宽和像素位置会影响视觉表现；客户的具体环境仍需升级后确认。

## 修复方式

仅对准星几何启用硬边像素绘制，避免抗锯齿额外降低像素覆盖率。保留原有物理像素尺寸、中心位置、颜色和统一不透明度组；100% 的已覆盖像素为实色，50% 仍为半透明，0% 完全隐藏。编辑器文字及其余界面继续使用原有渲染。

斜线和圆环边缘会呈现像素阶梯，这是保证细线实色的取舍。小数尺寸仍可调，但最终显示由物理像素栅格决定。小于 2 个物理像素的中心点采用方形像素绘制，避免硬边小圆点落在像素间隙而消失；较大的中心点仍为圆形。

Game Bar 使用独立的 UWP 绘制后端，本次不改变它遵循宿主 `RequestedOpacity` 的行为。如果使用 Game Bar，编辑器和 Game Bar 自身的不透明度均需检查。

## 验证边界

回归诊断直接读取 WPF 渲染结果的预乘 BGRA 像素，检查三种形状、细线、描边、中心点、不透明度与 DPI；它验证软件输出，不等同于客户显示器、HDR 或真实游戏环境的实测。

2026-10-29 本地验证：旧版在新诊断的实色像素检查上按预期失败；修复后 2,160 组实际 WPF 渲染通过，包括 100/125/150/175/200% DPI、奇偶像素尺寸、1/1.5/2/3 px 线宽、0/50/100% 不透明度及 1×/4× 预览中的小中心点。95 项必过桌面检查、35 项核心/协议检查、31 项 Game Bar 回归、16 项独立进程边界检查和 19 项安装器检查通过。Release 构建无警告、无错误。
